# Redis 스터디 발표 가이드

## 발표 목표

- Redis가 왜 빠른지 설명한다.
- Redis를 어디에 쓰는지 실무 사례로 연결한다.
- 데모 화면으로 각 기능이 실제로 어떻게 동작하는지 보여 준다.

## 추천 발표 흐름

### 1. Redis 한 줄 소개

`Redis는 메모리 기반의 고성능 key-value 저장소이고, 단순 캐시를 넘어서 자료구조 서버처럼 쓸 수 있다.`

### 2. 왜 빠른가

여기서는 아래 네 가지만 또렷하게 말하면 충분합니다.

1. 메모리 기반이라 디스크 I/O보다 훨씬 빠르다.
2. 단일 명령이 짧고 자료구조 연산이 단순하다.
3. 싱글 스레드 이벤트 루프라 컨텍스트 스위칭과 락 경합이 적다.
4. String, Set, Sorted Set 같은 자료구조가 내부적으로 최적화되어 있다.

### 3. 하지만 만능은 아니다

이 부분을 같이 말해야 설명이 균형 잡힙니다.

1. 메모리 비용이 비싸다.
2. 캐시는 정합성 이슈가 있다.
3. Pub/Sub는 durable queue가 아니다.
4. 분산 락은 잘못 구현하면 위험하다.

### 4. 화면으로 보여줄 순서

브라우저에서 다음 주소를 엽니다.

`http://localhost:8080/demo/redis`

그 다음 아래 순서대로 버튼을 눌러 설명하면 자연스럽습니다.

1. Basics
설명 포인트:
- Redis는 단순 문자열만 저장하는 게 아니라 자료구조 서버다.
- TTL이 있어서 만료 시간을 직접 줄 수 있다.
- Sorted Set은 점수 기반 정렬에 강하다.

2. Cache
설명 포인트:
- 같은 데이터를 두 번 읽어도 원본 조회는 한 번만 일어난다.
- 캐시 히트가 DB 부하를 줄인다.
- 대신 캐시 무효화가 필요하다.

3. Pub/Sub
설명 포인트:
- 이벤트를 채널로 발행하면 구독자가 즉시 받는다.
- 실시간 알림에는 유용하지만, 메시지 유실을 허용하지 않는 시스템에는 한계가 있다.

4. Lock
설명 포인트:
- 여러 서버가 동시에 같은 자원을 건드릴 때 Redis 락을 쓸 수 있다.
- 단순 `SET NX PX` 락은 토큰 검증이 중요하다.
- 운영에서는 Redisson 같은 검증된 라이브러리가 더 안전하다.

5. Leaderboard
설명 포인트:
- Sorted Set은 랭킹 시스템 구현에 매우 적합하다.
- 상위 N명 조회와 개별 순위 계산이 쉽다.

6. Rate Limit
설명 포인트:
- `INCR + EXPIRE` 만으로도 요청 제한이 가능하다.
- API 보호, 로그인 시도 제한에 자주 쓴다.

## 질문이 들어왔을 때 답변 포인트

### Redis와 DB 차이는?

- DB는 영속 저장과 복잡한 조회에 강함
- Redis는 빠른 조회와 단순한 자료구조 연산에 강함
- 둘은 경쟁 관계보다 역할 분담 관계에 가깝다

### 싱글 스레드인데 왜 병목이 안 생기나?

- 짧은 명령 위주에서는 오히려 락과 스레드 전환 비용이 줄어 유리하다
- 다만 긴 연산은 전체 지연을 키운다

### Pub/Sub와 Kafka 차이는?

- Redis Pub/Sub는 가볍고 빠르지만 내구성이 약하다
- Kafka는 메시지 보관, 재처리, consumer group에 강하다

### 분산 락을 꼭 Redis로 해야 하나?

- 아니다
- DB 락, ZooKeeper, etcd 같은 대안도 있다
- Redis는 빠르고 단순하지만 정확한 설계가 필요하다
