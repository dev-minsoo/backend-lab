## 🎯 실험 목적

### 검증하고자 하는 가설

1. Redis 캐시는 동일 키 반복 조회에서 원본 조회 횟수를 줄인다.
2. Sorted Set과 카운터 같은 연산은 애플리케이션 메모리 조합보다 단순하고 빠르게 처리된다.
3. Redisson 기반 락은 동시성 상황에서 재고를 안전하게 보호한다.

### 측정 지표

- 원본 조회 횟수
- 캐시 히트 여부
- 동시 요청 후 최종 재고 값
- 상위 랭킹 조회 결과
- Rate Limit 차단 여부

### 테스트 시나리오

### 시나리오 1: 캐시 반복 조회

- 동일한 상품을 여러 번 조회
- 첫 호출만 원본 조회를 수행하는지 확인

### 시나리오 2: 분산 락 기반 재고 차감

- 여러 스레드가 동시에 재고 차감을 시도
- 재고가 음수로 내려가지 않는지 확인

### 시나리오 3: 랭킹과 Rate Limit

- Sorted Set에 점수 저장 후 상위 사용자 확인
- 일정 시간 창에서 요청 횟수를 넘기면 차단되는지 확인

## 📊 측정 결과

| 항목 | 기대 결과 | 확인 포인트 |
|------|-----------|-------------|
| 캐시 조회 | 첫 호출만 원본 조회 | queryCount = 1 |
| Pub/Sub | 이벤트 수신 성공 | subscriber 이벤트 개수 |
| 단순 락 | 동일 키 중복 획득 불가 | 두 번째 acquire 실패 |
| Redisson 락 | 재고 음수 방지 | 최종 stock = 0 |
| 리더보드 | 점수순 정렬 | top N 순서 일치 |
| Rate Limit | 최대 요청 수 초과 시 차단 | 네 번째 요청 차단 |

## 🔍 분석

### 주요 발견사항

1. 캐시 챕터는 Redis 학습 대비 실무 활용도가 가장 높습니다.
2. Pub/Sub는 간단하지만 내구성 있는 메시징 시스템이 아니라는 점을 체감하기 좋습니다.
3. 락은 단순 구현도 가능하지만, 실무에서는 Redisson 같은 검증된 라이브러리 사용이 더 안전합니다.
4. Sorted Set과 카운터는 Redis 자료구조의 장점을 가장 직관적으로 보여 줍니다.

## 💡 결론

- Redis 종합편 v1은 입문에서 실무 연결까지 가장 중요한 패턴을 빠르게 체험하는 데 초점을 맞췄습니다.
- 다음 확장 주제로는 `session`, `streams`, `eviction`, `persistence` 를 붙이면 운영 관점까지 이어갈 수 있습니다.
